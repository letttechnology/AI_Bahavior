Two separate questions:

**Why prompts for git?**

Claude Code auto-allows all standard `git` read-only subcommands (`git status`, `git log`, `git diff`, etc.) — but only when the command starts with `git <subcommand>`. When you add a flag first like `git -C /path status`, the auto-allow logic sees `git -C` as the subcommand and doesn't recognise it. So it prompts. The fix I just added (`Bash(git -C * status *)` etc.) patches that gap.

**Why do we have to list allows when deny exists?**

Deny and allow are independent controls — deny doesn't imply allow for everything else. The default for anything not in either list is **prompt**. So the flow is:

1. Does the command match a `deny` rule? → **Block** (no prompt)
2. Does the command match an `allow` rule? → **Run** (no prompt)
3. Neither? → **Prompt the user**

The allow list exists specifically to skip the prompt for commands you've pre-approved. Without it, everything that isn't explicitly denied would still prompt — which is the default "ask before running" behaviour Claude Code ships with.
