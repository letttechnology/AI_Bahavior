### 9. InflectionEngineService COALESCE with `token_sense_override`

**File:** `D:\workspace-vscode\interlinear-bible-api\src\main\java\com\interlinear\bible\service\InflectionEngineService.java`

Three query methods use the same pattern (example from `fetchAllTokens`, lines 847–868):

```sql
SELECT
  vw.id AS verse_word_id, ...,
  COALESCE(ls_ai.gloss, ls.gloss, m.short_gloss) AS resolved_gloss,
  COALESCE(tso.sense_index, 0) AS sense_index,
  (tso.sense_index IS NOT NULL) AS has_ai_override,
  m.short_gloss AS corpus_gloss
FROM verse_word vw
LEFT JOIN lexeme l ON vw.lexeme_id = l.id
LEFT JOIN lexeme_meaning m ON m.lexeme_id = l.id AND m.source = 'corpus'
LEFT JOIN lexeme_sense ls ON ls.lexeme_id = l.id AND ls.sense_index = 0
LEFT JOIN token_sense_override tso ON tso.verse_word_id = vw.id
LEFT JOIN lexeme_sense ls_ai ON ls_ai.lexeme_id = l.id
  AND ls_ai.sense_index = tso.sense_index
ORDER BY vw.id
```

**Logic:** If `token_sense_override` has a row for this token, `ls_ai.gloss` (the AI-selected sense) is used. If not, `ls.gloss` (sense_index=0, the primary sense) is used. If that's also null, `m.short_gloss` (corpus fallback) is used. The `sense_index` is `COALESCE`d to 0 (default to primary sense when no override exists).
