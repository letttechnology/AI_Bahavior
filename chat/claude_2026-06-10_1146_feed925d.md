**Monorepo deployment to Kubernetes**

The monorepo is a *source organization* decision, not a deployment decision. Each app builds independently:

```
apps/reader/   → npm run build → dist/ → its own Dockerfile → its own Docker image
apps/studio/   → npm run build → dist/ → its own Dockerfile → its own Docker image
```

On Kubernetes these are completely separate objects:

```
Reader UI image  → Deployment + Service + public Ingress  (internet-facing)
Studio UI image  → Deployment + Service + NO Ingress      (cluster-internal only)
                   or: never deployed to K8s at all — dev-only
```

The Studio image never gets an external `Ingress` resource, so it's never reachable from outside the cluster. Alternatively you just don't deploy it to production at all — it runs only locally against local backends.

**Bottom line:** one git repo does not mean one deployment. You get two independent Docker images and two independent K8s manifests. The security boundary is at the Ingress layer, not at the source repo layer.
