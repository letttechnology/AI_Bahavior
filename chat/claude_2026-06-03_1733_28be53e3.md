## Scrum Story Lifecycle — Standard Phases

---

### 1. Backlog
- Story created by Product Owner
- High level — not yet ready to work on
- Needs refinement before it can be picked up

### 2. Ready (Definition of Ready)
A story cannot move to In Progress until ALL of these are true:
- Acceptance criteria written and clear
- Story is understood by the team
- Dependencies identified
- Small enough to complete in one sprint
- No blockers

### 3. In Progress
- Developer picks up the story and begins work
- Implements the feature
- Writes unit tests — part of the work, not after
- Updates any broken existing tests
- Code compiles clean
- All tests pass
- Peer code review done
- Meets acceptance criteria

### 4. In Review / Testing
- Work is complete per Definition of Done
- Handed to independent review or QA
- Tested against acceptance criteria
- If a defect is found — moves back to In Progress

### 5. Done (Definition of Done)
- All acceptance criteria met
- Code reviewed
- Tests written and passing
- No compile errors
- No known defects
- Accepted by Product Owner
- Ready to ship — nothing left for the next person to fix

Selection bias: Humans and agents write MEMORY.md entries for things they remember to write about. The most dangerous gaps are the things nobody thought to document.

Implicit vs explicit knowledge: The most valuable context is often the stuff that seemed too obvious to write down at the time.
The architectural fix
The solution isn't write better memory notes. It is automatic decision capture at the point of change.
