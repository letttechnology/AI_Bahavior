### 5. Round-Robin / Provider Cycling Logic

There are **three places** with provider cycling logic:

#### a) `SenseSelectionService.callAiWithFallback()` (Java — primary production logic)
```java
private String callAiWithFallback(String prompt) {
    int size = providerChain.size();
    if (size == 0) return null;
    int start = providerIndex.getAndIncrement() % size;  // round-robin starting position

    Exception lastException = null;
    for (int retry = 0; retry < 3; retry++) {
        for (int offset = 0; offset < size; offset++) {
            int idx = (start + offset) % size;
            try {
                return providerChain.get(idx).prompt()...call().content();
            } catch (Exception e) {
                boolean isRateLimit = e.getMessage() != null &&
                    (e.getMessage().contains("429") || ...);
                if (isRateLimit) {
                    // try next provider
                    continue;
                }
                // non-rate-limit error
                lastException = e;
            }
        }
        // All providers rate-limited — backoff and retry
        long waitMs = Math.min(2000L * (retry + 1), 30000L);
        Thread.sleep(waitMs);
    }
    return null;
}
```
- Round-robins the **starting provider** across calls via `AtomicInteger`
- On 429: **tries the next provider** in the chain (wraps around)
- After exhausting all providers: **retries up to 3 times** with exponential backoff

#### b) `ContextualGlossService.callAi()` (Java — simpler fallback only)
```java
private String callAi(List<Map<String, Object>> contentWords, String lang) {
    Exception lastException = null;
    for (int i = 0; i < providerChain.size(); i++) {
        try {
            return providerChain.get(i).prompt().user(prompt).call().content();
        } catch (Exception e) {
            if (isRateLimit && i < providerChain.size() - 1) {
                // try next provider
                lastException = e;
            } else {
                throw e;
            }
        }
    }
    throw new RuntimeException("All AI providers exhausted", lastException);
}
```
- **No** round-robin starting position — always starts at index 0
- **No** retry on all-exhausted — throws immediately
- Just tries next provider on 429

### 6. How the OpenAI Client Is Constructed/Used

All AI services use **Spring AI's OpenAI-compatible client** (`org.springframework.ai.openai.OpenAiChatModel` / `OpenAiApi`).

**Construction** (in `AiChatConfig.buildClient()`):
```java
private static ChatClient buildClient(String baseUrl, String apiKey, String model) {
    var api = OpenAiApi.builder()
        .baseUrl(baseUrl)
        .apiKey(apiKey)
        .build();
    var options = OpenAiChatOptions.builder()
        .model(model)
        .temperature(0.3)
        .build();
    var chatModel = OpenAiChatModel.builder()
        .openAiApi(api)
        .defaultOptions(options)
        .build();
    return ChatClient.builder(chatModel).build();
}
```

This works with **any OpenAI-compatible API**: Groq, Gemini, OpenAI, Mistral, Ollama, NVIDIA NIM, etc.

### Key Architectural Insight

**Only `SenseSelectionService` implements true round-robin provider cycling** with:
- `AtomicInteger providerIndex` for rotating starting position across calls
- Full provider chain traversal on 429 with wrap-around
- 3 retry cycles with exponential backoff when all providers are rate-limited

**`ContextualGlossService`** has a simpler fallback (sequential, no round-robin, no retry).

**All other services** (`WordInsightService`, `WordBreakdownService`, `MorphSuffixService`, `IrregularVerbEnrichmentService`, `AiTranslationService`, `LanguageGlossService`) use a **single `ChatClient`** from the primary builder — no provider list, no failover at all. They handle rate limiting via retry with backoff on the same client.
